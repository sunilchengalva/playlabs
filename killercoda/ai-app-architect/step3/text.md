# Step 3 — Explore a Variation

Show the audience that the AI adapts instantly when the brief changes. This demonstrates that the tool generalises — it is not a one-trick output.

## Run with a different brief

Try any of these, or compose your own:

```
python3 /root/demo/app_architect.py "Build a library book reservation system for a university"
```

```
python3 /root/demo/app_architect.py "Build a faculty leave management portal"
```

```
python3 /root/demo/app_architect.py "Build a smart campus parking allocation app"
```

## What to narrate

- **Before running** — "Let's change the brief completely and see if the structure holds."
- **As it generates** — "Same four sections. Different domain. The AI is not copying from a template — it is reasoning about the new problem."
- **At the end** — "The question for you as an educator: if your students can direct an AI to produce this in 15 seconds, what should the assignment ask them to do next? That's the curriculum design question Engineering 5.0 raises."

## The Engineering 5.0 point

The AI handled:
- Structuring the problem
- Making reasonable default assumptions
- Producing a complete starting architecture

The engineer still decides:
- Whether the assumptions are correct for the real context
- Which design tradeoffs to make
- What the security and privacy requirements are
- What the actual user research says about the user flow
